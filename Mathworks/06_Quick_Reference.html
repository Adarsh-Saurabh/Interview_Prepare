Quick Reference — Night Before / Day Of

The three facts that matter most

  1. Python is not allowed. C / C++ / Java / JavaScript only. Every project on your resume is Python. Fluency in C++ is your #1 risk. OFFICIAL
  2. You must use two different languages across the 3 coding questions. CS track has no opt-out (other tracks do). Do your second-language question first, while you're calm. OFFICIAL
  3. 90 minutes total for 3 coding questions + aptitude. ~22 min per coding question, ~20 min aptitude. OFFICIAL

Your language split — write it here before the test

Q_ → _ · Q_ → _ · Q_ → ___

Default plan: easiest question in Java, other two in C++.

Test-day triage

CODE
0:00–0:05   Read all 3. Rank easy → hard.
0:05–0:25   Easiest. SUBMIT.
0:25–0:48   Second. SUBMIT even if partial.
0:48–1:12   Hardest. Brute force FIRST, submit, then optimise.
1:12–1:30   Aptitude. Skip anything over 60s, return if time.

Working brute force > unfinished optimal. Never leave a question blank.

Before every submit — 20-second check

Empty input · single element · all identical · negatives and zero · max size · integer overflow (long long when multiplying) · off-by-one on loop bounds · v.size()-1 on an empty vector.

Python-brain traps in C++

7/2 == 3 · int overflows at 2.1e9 · v.size() is unsigned · locals contain garbage unless initialised · for (auto &x : v) to mutate · v.back() not v[-1] · "\n" not endl.

Interview: the MathWorks mindset in one line

They build tools for engineers whose products cannot fail. Correctness, testing, readability and clear interfaces beat cleverness and optimality — every time.

The four moves that score in every technical round

  1. Ask 2–3 clarifying questions before writing any code. Diving in is scored as a negative.

  2. Narrate continuously. Silence reads as stuck. State trade-offs out loud before choosing.

  3. Volunteer edge cases before you're asked for them.

  4. Answer "how would you test this?" properly. This is the MathWorks signature question and where you can beat stronger coders.

Edge-case checklist (recite for any function)

empty/null · single element · two elements · all identical · sorted / reverse sorted · boundaries (0, 1, −1, INT_MAX/MIN) · negatives · invalid input · duplicates · very large input · special characters and Unicode · round-trip property

Numerics one-liners (high value, low competition)

Never compare floats with == — use a relative epsilon · NaN != NaN is true · double ≈ 15–16 significant digits · catastrophic cancellation when subtracting near-equal numbers · summation order affects error · C/C++ is row-major, MATLAB and Fortran are column-major.

C++ must-knows

Virtual destructor or the derived part leaks on delete via base pointer · rule of three/five · shallow vs deep copy → double free · RAII (acquire in constructor, release in destructor) · const char* vs char* const (read right to left) · reference can't be reseated, pointer can · stack vs heap.

Your two scripted answers — rehearse out loud

"Why the CS track when your M.Tech is Signal & Image Processing?" → B.Tech is CS; the specialisation sits on top of a CS foundation. The part I enjoy is the software engineering side of image problems. I want to build the tools that image-processing engineers use — my domain knowledge makes me a better developer for that product, not a worse one.

"Why MathWorks?" → I've built HOG-based CV pipelines from scratch; MATLAB's Image Processing and Computer Vision toolboxes are the productised version of exactly that. Your customers build things that can't fail, so correctness and testing matter more than shipping speed — that's the discipline I want to learn early. And EDG's rotations mean I see development, testing and application engineering before specialising.

Do before the interview: 45 minutes in MATLAB Online (free, browser). Load an image, try extractHOGFeatures. Then you can say "when I tried it, I noticed..." — that clause proves the rest isn't rehearsed.

Project defence — the flashpoints

Claim Your prepared line
10,000×10,000 units Coordinate space, not node count — the search graph was ~10⁴ waypoints; I never materialised 10⁸ cells. Volunteer this yourself.
"optimal" paths Know whether your heuristic was admissible. If not, qualify the word.
<0.5s for 10,000+ locations One multi-source run or 10,000 separate searches? Timing method? Which i5?
96.45% accuracy Dataset, label source, test-set size. Four significant figures needs justifying — or round it. Offer precision/recall.
11× faster than ResNet Which ResNet, CPU vs GPU, same hardware, absolute fps for both, did you run it yourself.
"zero-hallucination" Reframe: the arithmetic runs in deterministic Python, the model only extracts values — so the maths can't hallucinate.
85% workload reduction Baseline process and sample size; were outputs verified correct or just completed.
98% token compression Lossy structured extraction, not lossless compression. What was discarded, and why it didn't matter.

Lead with PathMapper when asked "tell me about a project." Not Uplan.

When a number is challenged: "Fair question — let me be precise about what that measured, and where it's softer than the bullet suggests." Volunteering a limitation is a hiring signal at this company.

GD: five moves

Enter in the first 45–60s or after two speakers with a framing contribution · speak 4–6 times, 30–45s each, never more · credit someone by name and build on their point · bring in a silent member · volunteer the closing summary.

Fatal: dominating · silence · getting personal · repeating a made point · caving instantly, or refusing to update ever.

Questions to ask them (pick two)

  • How do the EDG rotations work in practice — how much say do you get?
  • What does the testing culture look like day to day?
  • Users have scripts that ran unchanged for a decade — how does that shape development decisions?
  • What separates EDG hires who thrive from those who struggle?

Not in technical/managerial rounds: salary, leave, WFH. Save for HR.

Logistics checklist

  • [ ] Both languages compile locally — verified today
  • [ ] Language split decided and written down
  • [ ] Charger · stable internet · phone hotspot backup
  • [ ] Government ID within reach (proctored tests ask)
  • [ ] Rough paper and pen
  • [ ] Water
  • [ ] All other tabs closed — assume tab-switch detection
  • [ ] Placement cell confirmed: round structure, GD or no GD, platform, cutoffs
  • [ ] Bangalore/Hyderabad flexibility answer ready (say yes if you can)
  • [ ] No-PhD answer ready

Sleep. 90 minutes of sustained concentration costs more when tired than one extra mock gains.

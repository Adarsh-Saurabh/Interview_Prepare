🧠 Core RAG, Vector Search & Agent Internals

Under The Hood

1. Bi-Encoder vs Cross-Encoder: The Latency vs Accuracy Trade-off

Architecture How It Operates Latency / Complexity Role in RAG Pipeline
Bi-Encoder (Embedding Models) Encodes Query $q$ and Document $d$ independently into vectors $ ec{u}$ and $ ec{v}$. Similarity computed via dot product: $\cos( ec{u}, ec{v})$. $O(1)$ fast dot-product over pre-computed index. Vectors can be searched across millions of chunks in milliseconds. First-Stage Retrieval: Fetches top 50-100 candidates from database. Cannot model token-level cross-interactions.
Cross-Encoder (Reranker Models) Passes Query AND Document together into self-attention layers: [CLS] Query [SEP] Document [SEP]. All tokens cross-attend! $O(N)$ heavy transformer inference for every document candidate. Too slow to run across the entire database! Second-Stage Reranker: Reranks top 50 candidates down to top 4 highest-relevance chunks for the LLM context window.

2. How HNSW (Hierarchical Navigable Small World) Works

HNSW is the dominant vector indexing algorithm in modern vector databases:

  • Multi-Layer Skip-List Graph: Vectors are organized in hierarchical layers. Top layers have sparse, long-range highway edges; bottom layer (Layer 0) has dense, short-range edges connecting all vectors.
  • Logarithmic Search ($O(\log N)$): Search begins at the top layer with greedy routing (hopping to the neighbor closest to the query vector). When a local minimum is hit, it drops to the next layer down and resumes until it reaches Layer 0.
  • Parameters: M (max bi-directional connections per node, controls memory) and efSearch / efConstruction (size of dynamic candidate list, controls recall vs query latency).

⚠️ High-Frequency GenAI & Agent Traps

Recruiter Traps
Trap #1: Why does Naive RAG fail in real production?

Recruiter favorite! Naive RAG (chunking text naively → embedding → top-K cosine similarity → send to LLM) suffers from three catastrophic failure modes:

  1. Semantic Disconnect / Keyword Misses: Dense embeddings excel at conceptual similarity but fail on exact part numbers, acronyms, or specific IDs (where BM25 keyword search dominates!).
  2. "Lost in the Middle" Phenomenon: LLMs attend strongly to the beginning and end of long prompts but ignore facts buried in the middle chunks of a 10-chunk context window.
  3. Chunk Boundary Truncation: Fixed 500-token chunks slice sentences or tables in half, destroying relational semantics.
💡 The RAG Triad for Hallucination Evaluation (TruLens / Ragas)

To scientifically evaluate RAG applications without human grading, industry uses the RAG Triad:

  • 1. Context Relevance: Is the retrieved context actually relevant to the user query? (Evaluates Retriever).
  • 2. Groundedness (Faithfulness): Is the LLM's answer completely grounded in the retrieved context, or did it invent external claims? (Evaluates Hallucination).
  • 3. Answer Relevance: Does the generated response directly answer what the user asked? (Evaluates Generator).

🎯 Interview Q&A Flashcards (Self-Assessment)

5 Questions
Q1: How do you prevent infinite loops in cyclic LangGraph multi-agent systems?
In LangGraph, infinite cyclic loops are prevented through three defensive mechanisms:
  1. Hard Recursion Limit: Pass config={"recursion_limit": 25} in app.invoke(), which forcibly throws a GraphRecursionError if the graph exceeds the threshold.
  2. State Step Counter: Add an integer retry_count: Annotated[int, operator.add] to the graph state. In conditional edge routing, if state["retry_count"] >= MAX_RETRIES, route to a fallback human-escalation or default response node instead of looping back to the planner.
  3. Deterministic Validator Gates: Ensure the validator has progressive relaxation criteria or unambiguous pass/fail boundaries.
Q2: What is Reciprocal Rank Fusion (RRF) and why is it used in Hybrid Search?
Cosine similarity scores (e.g. 0.82) from dense embeddings and BM25 scores (e.g. 14.5) operate on completely different numerical scales and cannot be directly summed.
RRF (Reciprocal Rank Fusion) normalizes rankings by combining only their ordinal ranks rather than raw scores: $$RRF(d) = \sum_{m \in M} rac{1}{k + rank_m(d)}$$ where $k$ is a constant (typically 60). Documents appearing in the top 5 of both BM25 and Dense search shoot to the top of the fused results!
Q3: What is the difference between Function Calling and ReAct?
• ReAct (Reason + Act): A prompt engineering pattern where the LLM is prompted to output structured thought chains: Thought → Action → Observation → Thought... Parses text output via regex/string formatting.
• Native Function Calling / Tool Calling: Model fine-tuning level capability (OpenAI, Anthropic, Gemini). The model natively emits valid, structured JSON conforming to a JSON Schema specification, bypassing fragile text parsing.
Q4: What is Pre-filtering vs Post-filtering in Vector Databases?
• Post-Filtering: Perform ANN vector search across the entire database to find top 100 vectors, then filter out items that don't match metadata (e.g. user_id == 42). Catastrophic flaw: If only 1% of docs belong to user 42, the top 100 might contain zero matching items!
• Single-Stage Filtered HNSW (e.g. Qdrant): During the graph traversal, the algorithm only considers hops between nodes that satisfy the metadata filter payload, guaranteeing accurate top-K results with zero recall loss.
Q5: What is Small-to-Big (Parent Document) Chunking?
Problem: Small chunks (100 tokens) yield accurate vector embedding matches because they contain focused semantics, but lack surrounding context for the LLM to generate answers. Large chunks (1000 tokens) provide rich context but dilute embedding vectors.

Small-to-Big Solution: Text is split into small child chunks (e.g. 150 tokens) for vector indexing. Each child chunk stores a reference to its larger parent document (e.g. 1000 tokens). Vector search matches against the child chunk, but the system retrieves and feeds the full parent chunk to the LLM context window!

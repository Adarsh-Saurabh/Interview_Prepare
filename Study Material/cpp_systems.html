# RAII & The Rule of 5 / Rule of 0

IMPORTANT The Rule of 5 for Resource-Managing Classes
If a class manages an acquired resource (raw pointer, file handle, socket, mutex), you must explicitly declare or delete all FIVE special member functions: 1. **Destructor**: `~MyClass()` — releases resource. 2. **Copy Constructor**: `MyClass(const MyClass&)` — deep copy. 3. **Copy Assignment**: `MyClass& operator=(const MyClass&)`. 4. **Move Constructor**: `MyClass(MyClass&&) noexcept` — steals pointer, zeroes source. 5. **Move Assignment**: `MyClass& operator=(MyClass&&) noexcept`. **Rule of Zero**: Prefer classes that manage NO raw resources directly (use `std::string`, `std::vector`, `std::unique_ptr`). The compiler auto-generates all 5 correctly!

# VTable Internal Layout & Virtual Destructors

C++ Virtual Table (VTable) Layout in Memory
🔍
IMPORTANT Why Base Classes MUST Have a Virtual Destructor
If a derived object is deleted through a pointer to its base class (`Base* ptr = new Derived(); delete ptr;`): • If `~Base()` is **NOT virtual**: The compiler resolves the destructor statically to `Base::~Base()`. The `Derived` destructor is NEVER invoked! Any resources allocated by `Derived` (heap memory, sockets, file locks) leak immediately. Undefined Behaviour under C++ standard. • If `~Base()` is **virtual**: The destructor is called dynamically via the vtable, executing `Derived::~Derived()` first, then chaining to `Base::~Base()` cleanly.

⚖️ Decision Matrix: shared_ptr Allocation Strategies

std::make_shared() USE WHEN: Allocates Managed Object T and Control Block in a SINGLE contiguous heap chunk. 1 allocation instead of 2. Cache friendly. AVOID WHEN: If large weak_ptrs outlive shared_ptrs, the entire combined memory block cannot be deallocated until all weak_ptrs die!
std::shared_ptr(new T()) USE WHEN: Need custom deleters, or when object T is massive and weak_ptrs persist for a long time. AVOID WHEN: Performs TWO separate heap allocations (`new T` and control block). Slower and fragments memory.

# Move Semantics & Universal References (Forwarding References)

TIP What std::move Actually Compiles To (The Big Interview Secret)
`std::move` generates **ZERO assembly instructions** and moves absolutely nothing at runtime! It is purely a compile-time `static_cast(x)` that unconditionally casts an lvalue to an rvalue (xvalue), allowing the compiler to select the move constructor instead of the copy constructor.
IMPORTANT Universal References & Reference Collapsing Rules
A template parameter `T&&` in a type-deducing context is a **Forwarding Reference** (Universal Reference), NOT an rvalue reference! Reference Collapsing Rules: • `&` + `&` → `&` • `&` + `&&` → `&` • `&&` + `&` → `&` • `&&` + `&&` → `&&` (Only rvalue + rvalue collapses to rvalue!) `std::forward(arg)` conditionally casts to rvalue only if `T` was deduced as a non-reference (preserving original argument category).
📄 perfect_forwarding_factory.cppcpp
#include <utility>
#include <memory>

// Perfect-Forwarding Factory Function
template <typename T, typename... Args>
std::unique_ptr<T> make_custom(Args&&... args) {
    // std::forward preserves whether each argument was lvalue or rvalue
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}

# 🚀 Lock-Free SPSC Ring Buffer & Memory Models

# Lock-Free Single-Producer Single-Consumer (SPSC) Ring Buffer

TIP The Holy Grail of Low-Latency Systems (Pace / HFT Core)
An SPSC ring buffer enables communication between a network-polling thread and a trading-logic thread with ZERO mutex locks, ZERO context switches, and sub-10ns latency using acquire-release atomics and cache-line padding.
📄 lockfree_spsc_queue.hppcpp
#include <atomic>
#include <cstddef>
#include <new>

template <typename T, size_t Capacity>
class LockFreeSPSCQueue {
    static_assert((Capacity & (Capacity - 1)) == 0, "Capacity must be power of 2");

    alignas(64) T buffer_[Capacity]; // Cache-line aligned buffer

    // Head (Reader index) padded to separate 64-byte cache line
    alignas(64) std::atomic<size_t> head_{0};

    // Tail (Writer index) padded to separate 64-byte cache line to prevent False Sharing!
    alignas(64) std::atomic<size_t> tail_{0};

public:
    // Producer pushes element into queue (Lock-Free)
    bool push(const T& item) {
        const size_t current_tail = tail_.load(std::memory_order_relaxed);
        const size_t current_head = head_.load(std::memory_order_acquire);

        if ((current_tail - current_head) == Capacity) {
            return false; // Queue full
        }

        buffer_[current_tail & (Capacity - 1)] = item;
        // Release ordering guarantees item write is visible before tail is updated!
        tail_.store(current_tail + 1, std::memory_order_release);
        return true;
    }

    // Consumer pops element from queue (Lock-Free)
    bool pop(T& item) {
        const size_t current_head = head_.load(std::memory_order_relaxed);
        const size_t current_tail = tail_.load(std::memory_order_acquire);

        if (current_head == current_tail) {
            return false; // Queue empty
        }

        item = buffer_[current_head & (Capacity - 1)];
        // Release ordering guarantees item read before head update is visible to writer
        head_.store(current_head + 1, std::memory_order_release);
        return true;
    }
};

# 🎯 High-Yield C++ Systems Interview Flashcards

What happens if a virtual function is called inside a C++ constructor?
P1 C++ Classic Weed-Out
During base class construction, the derived class members have NOT yet been constructed! The C++ runtime temporarily sets the object's `__vptr` to the **Base class VTable**. Calling a virtual function inside the constructor resolves to the **Base class implementation**, NOT the derived class override! Polymorphic dispatch is intentionally disabled during object construction to prevent accessing uninitialized derived member variables.
Rate Recall:
Why is 'return std::move(x);' an anti-pattern when returning a local object by value?
P1 Modern C++ Trap
Returning a local object by value allows the compiler to perform **Named Return Value Optimization (NRVO)**, constructing the object directly in the caller's stack frame with **ZERO copies and ZERO moves**! If you write `return std::move(x);`, you explicitly cast `x` to an rvalue reference, which forces the compiler to disable NRVO and invoke the move constructor instead! Only use `std::move` when returning a function parameter or class member.
Rate Recall:
What is Object Slicing and how do you prevent it?
P1 OOP Internals
Object Slicing occurs when an instance of a Derived class is assigned or passed by value to an object of Base class type (`Base b = derived;`). The compiler copies only the Base slice of the object, slicing away all derived member variables and resetting the `__vptr` to the Base vtable! Polymorphism is completely lost. Prevention: Always pass polymorphic objects by pointer or reference (`const Base&`).
Rate Recall:
Why does High-Frequency Trading (HFT) strictly ban malloc/free on the hot path?
P1 HFT Architecture (Pace ₹41L)
1. **Non-Deterministic Latency**: `malloc()` acquires internal heap bucket mutex locks and may trigger the `mmap`/`brk` kernel system call if the arena is exhausted, causing unpredictable latency spikes of up to 10 microseconds. 2. **Memory Fragmentation**: Dynamic allocations scatter memory across non-contiguous heap addresses, causing severe L1/L2 cache misses. 3. **HFT Strategy**: Pre-allocate all data structures at startup in contiguous static buffers or fixed-size pool allocators.

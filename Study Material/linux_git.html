# ⚡ 15-Min Sprint: Server Diagnosis & Git Mental Model

CLI & Server
🗣️ 15-SECOND INTERVIEW ANSWER

"When an interviewer asks 'The production server is slow, what do you run?', memorize the strict diagnosis order: top (CPU/load) -> free -h (RAM/swap) -> df -h / iostat (Disk I/O) -> ss -tulpn (Socket/Network queues)."

Every engineer uses Linux and Git daily, yet candidates freeze when asked about permissions, zombie process reaping, or unlinking open file descriptors.

🔍 The 4 Areas of Git: Working Tree -> Staging Area -> Local HEAD -> Remote Origin

# 🐙 Git Internals, Merge vs Rebase & Surgery

Git Depth
⚖️ Decision Matrix: Git Operations: Merge vs Rebase
Option / PatternPrime Use-Cases (Best Choice)Anti-Patterns / Failure Points
git merge USE WHEN: Feature branch into main. Preserves complete historical context and exact timeline commits. AVOID WHEN: Local unpushed feature branches where clean linear history is desired.
git rebase USE WHEN: Updating a local unpushed feature branch against latest main to create a clean, linear PR history. AVOID WHEN: Shared public branches! Never rebase commits that other engineers have pulled.
CommandWhat It ChangesSafety & RecoveryCanonical Use-Case
git reset --soft HEAD~1Moves HEAD back by 1 commit. Working directory & Staging index UNTOUCHED.100% Safe.Rewording commit message or combining changes.
git reset --hard HEAD~1Discards commit, staging index, AND local working directory edits!⚠️ Dangerous (Can recover via git reflog).Completely throwing away broken experimental code.
git revert <commit>Appends a NEW commit that applies the inverse diff of target commit.100% Safe for shared branches.Undoing a broken commit pushed to shared main.

# 💾 Inode Exhaustion & Disk Space Anomalies

Linux Traps
⚠️ INTERVIEW TRAP The Classic Trap: 'df -h' says Disk Full, but 'du -sh' says files are small!
A process opened a massive log file (e.g. 50GB) and another developer ran rm app.log. The directory entry is deleted, so du cannot find it! However, because the running process still holds an open file descriptor, the Linux kernel does not reclaim the disk blocks! Run lsof +L1 to locate the deleted file held open, and restart or kill the process to immediately free disk space.

# 🎯 28 Top Tech Interview Q&As

Assessment
What is the difference between kill and kill -9 (SIGTERM vs SIGKILL)?
EasySignalsAppleQualcomm
SIGTERM (kill PID / signal 15) politely asks the process to terminate, allowing it to execute cleanup handlers, flush files, and close network sockets. SIGKILL (kill -9 / signal 9) cannot be caught or ignored; the Linux kernel immediately terminates the process without cleanup.

Why should every shell script start with 'set -euo pipefail'?
MediumBashAll Companies
-e exits immediately on any command failure; -u treats unset variables as errors; -o pipefail ensures pipeline exit codes reflect the first failing command instead of only the last command. Prevents silent catastrophic failures in deployment scripts.

You ran 'git reset --hard' and lost 3 days of work. How do you recover it?
MediumGit RecoveryGoogleMeta
Run 'git reflog'. Git reflog maintains an append-only log of where HEAD has pointed locally over the last 30-90 days. Find the SHA before the reset and run 'git reset --hard ' to restore your work.
Rate Recall:
Why must PID 1 in a Linux container reap zombie child processes?
HardContainersDockerKubernetes
In Unix, when a process terminates, it remains a 'zombie' until its parent calls wait(). If the parent terminates first, orphaned children get reparented to PID 1. If PID 1 does not implement a reaping loop, zombie processes accumulate and exhaust the kernel PID table.

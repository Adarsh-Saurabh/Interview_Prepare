TIP Why the Stack and Heap Grow Toward Each Other
Stack grows downwards (from high address to low) because function frames are temporary and bounded by stack limits (default 8MB on Linux). Heap grows upwards (via `brk()` / `sbrk()` and `mmap()`). Placing them at opposite ends of the user space maximizes the contiguous unallocated dynamic growth zone without requiring rigid compile-time size partitions.

# 🔒 Synchronization, Peterson & Banker's Algorithm

# Peterson's Algorithm: 3 Requirements of Critical Section

IMPORTANT The 3 Non-Negotiable Critical Section Requirements
1. **Mutual Exclusion**: If process Pi is executing in its critical section, no other process can be in its critical section. 2. **Progress**: If no process is in its critical section and some wish to enter, only those not in their remainder section can participate in deciding who enters next, and this selection cannot be postponed indefinitely. 3. **Bounded Waiting**: There must be a bound on the number of times other processes are allowed to enter their critical sections after a process has made a request to enter and before that request is granted (prevents starvation).
📄 petersons_algorithm.cc
// Peterson's Algorithm for 2 processes P0 and P1
volatile bool flag[2] = {false, false};
volatile int turn = 0;

void process(int i) {
    int j = 1 - i; // Other process
    
    // Entry Section
    flag[i] = true;          // Declare intent to enter
    turn = j;                // Generously yield turn to other process
    
    // Busy wait while other process wants to enter and it's their turn
    while (flag[j] && turn == j) {
        // Wait (Spinlock)
    }
    
    // --- CRITICAL SECTION ---
    // Safe access to shared resources
    
    // Exit Section
    flag[i] = false;         // Release intent
    
    // Remainder Section
}
TIP Modern Hardware Warning: Why Peterson's Fails on x86/ARM Without Memory Barriers
Modern CPUs feature Out-of-Order Execution and Store Buffers. Without memory fences, the CPU or compiler can reorder `flag[i] = true;` and `turn = j;`, or delay making the write visible to the other core. Both processes can read `flag = false` simultaneously and enter the critical section together! In modern C++, `std::atomic` with `std::memory_order_seq_cst` is mandatory.

# The 4 Coffman Conditions & Deadlock Strategies

Coffman ConditionWhat It MeansHow to Prevent It (Break Condition)
1. Mutual ExclusionResources cannot be shared simultaneouslyMake resources shareable (e.g. read-only files). Usually impossible for printers/writers.
2. Hold and WaitProcess holds resources while requesting moreRequire process to request ALL resources upfront, or release held resources before requesting.
3. No PreemptionResources cannot be forcibly taken from a processIf request cannot be granted immediately, OS preempts all currently held resources.
4. Circular WaitP0 waits for P1, P1 waits for P2... Pn waits for P0Impose a global total ordering on all resources (e.g., $F: R \to \mathbb{N}$). A process can only request resource $R_j$ if $F(R_j) > F(R_i)$.
⚖️ Decision Matrix: Deadlock Handling Strategies
Option / PatternPrime Use-Cases (Best Choice)Anti-Patterns / Failure Points
Deadlock Prevention USE WHEN: Enforce strict compile/runtime protocols that break at least one of the 4 Coffman conditions. AVOID WHEN: Low resource utilization and possible starvation.
Deadlock Avoidance (Banker's) USE WHEN: OS dynamically inspects resource allocation state before granting requests to ensure system stays in a Safe State. AVOID WHEN: Requires processes to declare their MAXIMUM resource claim in advance, which is rarely known in general OS applications.
Deadlock Detection & Recovery USE WHEN: Allow deadlocks to occur; periodically run cycle detection on Resource Allocation Graph (Wait-For Graph) and abort processes. AVOID WHEN: High recovery overhead; aborting processes can corrupt external state or waste CPU hours.
Ostrich Algorithm (Ignore) USE WHEN: Stick head in sand and pretend deadlock never happens (used by Linux, Windows, macOS). AVOID WHEN: When deadlocks are exceedingly rare and cost of prevention exceeds reboot cost.

# Worked Numerical 1: CPU Scheduling Gantt Charts Compared

📐 WORKED PROBLEM

Scheduling Comparison on Identical Process Set: P1(0, 8), P2(1, 4), P3(2, 9), P4(3, 5)

Step 1 FCFS Execution
Order: P1(0-8) → P2(8-12) → P3(12-21) → P4(21-26). Turnaround Times: P1=8, P2=11, P3=19, P4=23. Avg Turnaround = 15.25 ms. Waiting Times: P1=0, P2=7, P3=10, P4=18. Avg Waiting Time = 8.75 ms.
Step 2 SJF (Non-Preemptive)
At t=0, only P1 arrives → executes P1(0-8). At t=8, P2, P3, P4 are ready. Shortest burst is P2(4) → executes P2(8-12). Next shortest is P4(5) → P4(12-17). Finally P3(9) → P3(17-26). Avg Waiting Time = (0 + 7 + 15 + 9)/4 = 7.75 ms.
Step 3 SRTF (Preemptive SJF)
At t=0: P1 runs. At t=1: P2 arrives (burst 4 < remaining P1 7) → preempts P1! P2 runs (1-5). At t=5: remaining bursts are P4(5), P1(7), P3(9). P4 runs (5-10). P1 runs (10-17). P3 runs (17-26). Avg Waiting Time = (9 + 0 + 15 + 2)/4 = 6.5 ms (Optimal!).
Step 4 Round Robin (q = 4 ms)
Gantt timeline: P1(0-4) → P2(4-8, finishes!) → P3(8-12) → P4(12-16) → P1(16-20, finishes!) → P3(20-24) → P4(24-25, finishes!) → P3(25-26, finishes!). Avg Waiting Time = (12 + 3 + 15 + 17)/4 = 11.75 ms.

SRTF achieves the minimal average waiting time (6.5 ms), while Round Robin provides the highest interactive responsiveness with fair time slicing.

# Worked Numerical 2: Page Replacement Traces & Belady's Anomaly

📐 WORKED PROBLEM

Page Reference String: [1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5] across 3 vs 4 Frames

Step 1 FIFO with 3 Frames
Initial faults on 1, 2, 3 (3 frames filled). Fault on 4 replaces 1. Fault on 1 replaces 2. Fault on 2 replaces 3. Fault on 5 replaces 4. Hits on 1, 2. Fault on 3 replaces 1. Fault on 4 replaces 2. Fault on 5 replaces 5. Total Page Faults = 9 faults.
Step 2 FIFO with 4 Frames (Belady's Anomaly!)
Frame capacity increased from 3 to 4. Tracing FIFO on the exact same string yields: Faults on 1, 2, 3, 4. Hits on 1, 2. Fault on 5 replaces 1. Fault on 1 replaces 2. Fault on 2 replaces 3. Fault on 3 replaces 4. Fault on 4 replaces 5. Fault on 5 replaces 1. Total Page Faults = 10 faults! (More memory caused MORE page faults!).
Step 3 LRU with 3 Frames
Evicts page not used for the longest period. Stack-based algorithm. Total Faults = 10 faults. Proven immune to Belady's Anomaly because it is a Stack Algorithm ($M(k) \subseteq M(k+1)$).
Step 4 Optimal (Bélády's Algorithm)
Evicts page whose next reference is furthest in the future (theoretical lower bound). Total Page Faults = 7 faults.
👁️ Click to Reveal Final Verification & Answer
Belady's anomaly occurs under FIFO because FIFO is not a stack algorithm; increasing memory frames from 3 to 4 paradoxically increases page faults from 9 to 10.

# 🧠 Multi-Level Page Tables, CFS & File Systems

# Virtual Memory & Multi-Level Page Table Size Arithmetic

IMPORTANT Standard Interview Weeder Problem: 48-bit Virtual Address Space Size
Question: 'In a 64-bit architecture with 48-bit virtual address space, 4KB page size, and 8-byte Page Table Entries (PTE), how much memory does a single-level page table require per process?' • Page Size = $4\text{KB} = 2^{12}\text{ bytes}$, so Offset = 12 bits. • Virtual Page Number (VPN) = $48 - 12 = 36\text{ bits}$. • Number of Pages = $2^{36} \approx 68.7\text{ billion pages}$. • Size of Single-Level Page Table = $2^{36} \times 8\text{ bytes} = 2^{39}\text{ bytes} = \mathbf{512\text{ GB}}$ per process! Conclusion: A single-level page table is completely impossible. Modern x86-64 uses a 4-Level Page Table (PML4 → PDPT → PD → PT) where levels are allocated dynamically on-demand, consuming only a few megabytes for typical processes.

# Linux Completely Fair Scheduler (CFS) Internals

CFS Architecture DimensionImplementation DetailWhy It Replaced the O(1) Scheduler
Core Metric`vruntime` (Virtual Runtime)Tracks the normalized CPU time spent by a task: $vruntime += \Delta exec\_time \times \frac{NICE\_0\_LOAD}{weight}$.
Data StructureSelf-Balancing Red-Black Tree (`rb_node`)Tasks ordered by `vruntime`. The leftmost node `rb_leftmost` has the lowest `vruntime` and is picked next in $O(1)$ time.
Fairness PrincipleProportional CPU share based on task `nice` valueA high-priority task (lower nice value) accumulates `vruntime` slower, receiving more physical CPU execution time.
Handling Sleep / I/O`vruntime = \max(vruntime, min\_vruntime)`Prevents I/O-bound tasks that slept for a long time from monopolizing the CPU when they wake up!

# 🎯 Top Tech Interview Flashcards & Defenses

# 🎯 High-Yield Operating Systems Interview Flashcards

Why is a system call (~100x) more expensive than a regular function call?
P0 Core Systems
A standard function call executes a `call` instruction, pushing the return address onto the stack and jumping within the same address space (takes ~1-2 ns). A system call requires an explicit CPU ring transition from User Mode (Ring 3) to Kernel Mode (Ring 0) via the `syscall` instruction. The CPU hardware switches to the kernel stack, saves user registers, verifies security boundaries, loads the kernel interrupt descriptor table (IDT), executes the privileged handler, and transitions back via `sysret`. This costs ~100-200 ns.
Rate Recall:
What causes Thrashing in virtual memory, and how does the OS detect and resolve it?
P0 Virtual Memory
Thrashing occurs when the sum of working set sizes of all active processes exceeds available physical RAM. The OS spends more time servicing page faults and swapping pages in/out of disk than executing actual CPU instructions, causing CPU utilization to plummet to near 0%. The OS detects this via Page Fault Frequency (PFF). Resolution: Suspend or terminate some processes (reduce degree of multiprogramming) to allow the remaining processes to fit their working sets into RAM.
Rate Recall:
What is the difference between a Zombie Process and an Orphan Process?
P0 Process Management
A Zombie Process is a process that has completed execution via `exit()`, but its entry remains in the Process Table because its parent has not yet called `wait()` or `waitpid()` to read its exit status code. Consumes process IDs (PIDs). An Orphan Process is a process whose parent terminated while the child was still running. It is automatically adopted by `init` / `systemd` (PID 1), which periodically reaps its exit status when it finishes.
Rate Recall:
Explain Priority Inversion and the Priority Inheritance solution (Mars Pathfinder bug).
P0 Concurrency & Real-Time
Priority Inversion occurs when a low-priority task (L) holds a shared mutex needed by a high-priority task (H), but a medium-priority task (M) preempts L (because M has higher priority than L). H is now indirectly starved by M! In the 1997 Mars Pathfinder mission, this caused system watchdog resets. Solution: Priority Inheritance Protocol — when high-priority task H blocks on a lock held by low-priority task L, L temporarily inherits the priority of H until it releases the lock.
Rate Recall:
Why can a spinlock cause deadlock on a uniprocessor system if interrupts are enabled?
P0 Systems Internals
On a single CPU core, if a process running in user mode acquires a spinlock, and an interrupt handler triggers on the same CPU that attempts to acquire the exact same spinlock, the interrupt handler will busy-wait (spin) forever waiting for the lock to be released. But the lock holder can never run to release the lock because the interrupt handler has preempted it on the only CPU! Solution: Spinlocks in kernel space must always disable local interrupts before acquiring the lock.

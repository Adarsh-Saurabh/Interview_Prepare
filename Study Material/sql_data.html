# ⚡ 15-Min Sprint: Logical Query Order & Joins

SQL Fundamentals
🗣️ 15-SECOND INTERVIEW ANSWER

"SQL queries are written starting with SELECT, but executed by the engine starting with FROM: understanding the strict 8-step logical order resolves why aliases cannot be used in WHERE clauses and why window functions evaluate after HAVING."

🔍 Strict 8-Step Logical Query Execution Order in SQL Engines
SQL Join TypeRow Matching ConditionUnmatched Rows Retained?Common Pitfalls & Traps
INNER JOINReturns rows where join condition evaluates to TRUE.No (unmatched discarded).Silently eliminates entities with zero transactions.
LEFT JOINAll rows from Left table + matching from Right.Left table preserved; Right filled with NULLs.Adding WHERE right.col = 'val' turns LEFT into INNER join!
FULL OUTERAll rows from both tables matched where possible.Both sides preserved with NULL padding.Expensive full hash/merge join scan.
CROSS JOINCartesian product ($M \times N$ rows).All permutations.Explodes memory; useful for generating date spines.
SELF JOINJoining a table to itself under distinct aliases.Depends on INNER vs LEFT.Employee-Manager hierarchies, consecutive events.

# 🪟 Window Functions & Frame Clauses

Windowing
FunctionRanking on Tied Values (e.g. Scores 100, 100, 95)Skips Next Rank?Canonical Use-Case
ROW_NUMBER()Assigns sequential integers: 1, 2, 3No gapsDeduplicating rows, fetching latest event.
RANK()Assigns identical rank to ties: 1, 1, 3Yes (gap of 2)Competition leaderboards, Olympic medals.
DENSE_RANK()Assigns identical rank to ties: 1, 1, 2No gapsNth highest salary across departments.
📄 2nd Highest Salary per Departmentsql
-- Fetching 2nd Highest Salary per Department using DENSE_RANK()
WITH RankedSalaries AS (
    SELECT 
        department_id,
        employee_id,
        salary,
        DENSE_RANK() OVER (
            PARTITION BY department_id 
            ORDER BY salary DESC
        ) AS rank_num
    FROM employees
)
SELECT department_id, employee_id, salary
FROM RankedSalaries
WHERE rank_num = 2;

# Pattern 1: Gaps and Islands (Finding Consecutive Login Streaks)

📄 Gaps & Islands Consecutive Streaksql
-- Gaps and Islands: Grouping consecutive active days
WITH NumberedLogins AS (
    SELECT 
        user_id,
        login_date,
        ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date) AS rn
    FROM user_logins
),
Islands AS (
    SELECT 
        user_id,
        login_date,
        -- The difference between a date and a consecutive sequence is constant!
        login_date - CAST(rn AS INTERVAL DAY) AS island_id
    FROM NumberedLogins
)
SELECT 
    user_id,
    MIN(login_date) AS streak_start,
    MAX(login_date) AS streak_end,
    COUNT(*) AS streak_length_days
FROM Islands
GROUP BY user_id, island_id
HAVING COUNT(*) >= 3;

# Pattern 2: Running Total with Frame Clauses

📄 Running Total with ROWS BETWEENsql
SELECT 
    customer_id,
    order_date,
    amount,
    SUM(amount) OVER (
        PARTITION BY customer_id 
        ORDER BY order_date
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS running_customer_spend
FROM orders;

# ⚡ Big Data Engineering & Skew Salting

Data Eng Depth
⚡ PRO TIP Data Skew in Spark Joins: The 'Salting' Fix
When joining on a skewed key (e.g. 50% of orders belong to a guest user ID = NULL or 0), all those rows hash to a single Spark executor, causing 99 tasks to finish in 10 seconds while the 100th task runs for 3 hours! Fix by Salting: append a random integer 0..N to the skewed key on the large table, and explode the small lookup table by N keys before joining.

# 🧭 Writing SQL You Cannot Execute (Palantir Drill)

FDE Core

Palantir's FDSE Learning round reportedly tests writing complex SQL against a database schema where you cannot execute queries or see query outputs. Follow this structured 5-step verbal protocol:

Step in ProtocolSpoken Script to InterviewerWhat It Proves
1. Restate Grain'First, let's verify: the grain of table A is one row per order item, while table B is one row per invoice.'Prevents duplicate fan-out bugs before writing.
2. State Join Keys & Cardinality'I am joining on order_id. This is a 1-to-many relationship, so I anticipate row multiplication.'Demonstrates deep relational understanding.
3. Defensive NULL Handling'Because this column can be NULL, I am wrapping it in COALESCE to prevent silent aggregation drop.'Shows production robustness.
4. Defensive Execution Order'Notice that I filter with WHERE before aggregating, rather than filtering in HAVING.'Shows query optimization instincts.

# 🎯 33 Top Tech Interview Q&As

Assessment
What is the difference between WHERE and HAVING?
EasySQL BasicsPalantirSwiggy
WHERE filters individual rows BEFORE they are grouped by GROUP BY. HAVING filters aggregated groups AFTER GROUP BY has evaluated. You cannot use aggregate functions like SUM() in a WHERE clause.

Why does 'WHERE col NOT IN (SELECT other_col FROM table)' return zero rows if any other_col is NULL?
HardSQL TrapsAppleCred
Because in three-valued SQL logic, if the subquery returns even a single NULL, 'col != NULL' evaluates to UNKNOWN. The NOT IN condition evaluates to UNKNOWN for all rows, causing the entire query to return zero rows! Use NOT EXISTS instead.
Rate Recall:
What is the difference between UNION and UNION ALL?
EasyPerformanceMedia.netAmazon
UNION ALL concatenates datasets directly without deduplication (O(N) fast). UNION performs an expensive sort or hash operation to deduplicate rows (O(N log N) slow). Always prefer UNION ALL unless deduplication is required.
Rate Recall:
Explain the difference between ROW_NUMBER(), RANK(), and DENSE_RANK().
MediumWindowingPalantirGoogle
On tied scores (e.g. 100, 100, 90): ROW_NUMBER() gives 1, 2, 3 (no ties). RANK() gives 1, 1, 3 (ties share rank, next rank is skipped). DENSE_RANK() gives 1, 1, 2 (ties share rank, no gaps in numbering).
Rate Recall:
What causes data skew in distributed Spark joins, and how does 'salting' resolve it?
HardBig DataPalantir FDSEMeta
Data skew happens when an uneven distribution of join keys causes most rows to route to a single executor. Salting appends a random prefix (0..K) to the skewed key on the large table and replicates keys on the small table, distributing load across K executors.
Rate Recall:
What is the 'grain' of a database table?
MediumData ModelingPalantirSalesforce
The level of detail represented by a single row in the table (e.g., 'one row per customer order line item' vs 'one row per invoice'). Knowing the grain is essential to prevent fan-out duplicate errors during joins.

# The Three Foundational Performance Equations

\text{CPU Time} = \text{Instruction Count (IC)} \times \text{CPI} \times \text{Clock Period } (T_c) = \frac{\text{IC} \times \text{CPI}}{\text{Clock Frequency } (f)}
🗣️ Spoken Reading: CPU execution time is the product of instructions executed, average cycles per instruction, and clock period
SymbolMeaning & Units
\text{IC}Total dynamic instruction count executed by the binary (determined by compiler & ISA).
\text{CPI}Average Cycles Per Instruction (determined by CPU microarchitecture, pipeline stalls, and cache misses).
T_c = 1/fClock cycle time in seconds (determined by semiconductor fabrication and longest pipeline stage delay).
🎯 Practical System Takeaway: A compiler optimization that decreases IC might increase CPI (e.g. replacing simple ALU ops with slow unrolled loops). Real performance requires minimizing the full product!
\text{Speedup} = \frac{1}{(1 - p) + \frac{p}{s}} \quad \xrightarrow{s \to \infty} \quad \text{Max Theoretical Speedup} = \frac{1}{1 - p}
🗣️ Spoken Reading: Amdahl's Law states overall speedup is strictly bounded by the serial fraction of the execution workload
SymbolMeaning & Units
pParallelizable fraction of the execution runtime (between 0.0 and 1.0).
sSpeedup factor achieved on the parallelizable fraction (number of CPU cores).
1 - pInherently serial portion that cannot be parallelized.
🎯 Practical System Takeaway: If a program is 90% parallel (p = 0.90), the maximum possible speedup on INFINITE processors is 1 / (1 - 0.9) = 10×! The serial 10% dominates total execution time.
\text{AMAT} = t_{\text{L1\_hit}} + m_{\text{L1}} \left( t_{\text{L2\_hit}} + m_{\text{L2}} \left( t_{\text{L3\_hit}} + m_{\text{L2}} \cdot t_{\text{DRAM\_penalty}} \right) \right)
🗣️ Spoken Reading: Average Memory Access Time across a multi-level cache hierarchy
SymbolMeaning & Units
t_{\text{hit}}Latency in cycles to access the cache level upon a hit.
mLocal miss rate at the corresponding cache level.
t_{\text{penalty}}Miss penalty latency to retrieve the line from the next level down.
🎯 Practical System Takeaway: Because DRAM latency is ~200 cycles, even a tiny 1% miss rate at L3 dramatically degrades effective CPI!

# 📊 5-Stage RISC Pipeline & Forwarding

# 5-Stage Classic RISC Pipeline Architecture

5-Stage RISC Pipeline Execution and Hardware Forwarding Paths
🔍
TIP Why Forwarding Cannot Eliminate the Load-Use Hazard Stall
Consider: `LW R1, 0(R2)` (Load Word into R1) `ADD R3, R1, R4` (Add depends on R1) In the pipeline: When `LW` is in the EX stage, memory has NOT yet been read (data is only fetched in the **MEM** stage). But `ADD` enters the EX stage in the very next cycle and needs the value of `R1` at the beginning of EX! Forwarding cannot send data backwards in time from the end of MEM to the start of EX in the same cycle. The hardware hazard detection unit must stall the pipeline by inserting **1 bubble cycle**, freezing PC and IF/ID registers.

# MESI Cache Coherence Protocol State Machine

IMPORTANT False Sharing: The Silent Multicore Performance Killer
**Definition**: False sharing occurs when two threads on different CPU cores modify completely independent variables that happen to reside on the **exact same 64-byte cache line**. • Core 0 writes `struct.a` → MESI invalidates the entire 64-byte cache line on Core 1! • Core 1 writes `struct.b` → MESI invalidates the entire 64-byte cache line on Core 0! • The cache line bounces ping-pong across the interconnect bus, degrading throughput by 10× to 50×! **Production Fix**: Align independent concurrent variables to distinct cache lines using C++17 `alignas(64)` or padding: `struct alignas(64) ThreadData { uint64_t counter; };`

# 📐 Worked Numericals: Amdahl, AMAT & Cache Bits

# Worked Numerical 1: Cache Address Bit Breakdown (Tag, Index, Offset)

📐 WORKED PROBLEM

System: 32-bit Address, 32 KB 4-Way Set Associative Cache, 64-Byte Cache Lines

Step 1 Calculate Block Offset Bits (b)
Line size = $64\text{ bytes} = 2^6\text{ bytes} \implies b = 6\text{ bits}$.
Step 2 Calculate Total Sets in Cache
$$\text{Total Lines} = \frac{\text{Cache Size}}{\text{Line Size}} = \frac{32 \times 1024}{64} = 512\text{ lines}$$ $$\text{Number of Sets (S)} = \frac{\text{Total Lines}}{\text{Associativity}} = \frac{512}{4} = 128\text{ sets}$$
Step 3 Calculate Set Index Bits (s)
$128\text{ sets} = 2^7\text{ sets} \implies s = 7\text{ bits}$.
Step 4 Calculate Tag Bits (t)
$$\text{Tag Bits} = \text{Total Address Bits} - s - b = 32 - 7 - 6 = \mathbf{19\text{ bits}}$$
👁️ Click to Reveal Final Verification & Answer
32-bit physical address is parsed by hardware into: Tag (19 bits) | Set Index (7 bits) | Byte Offset (6 bits).

# Worked Numerical 2: 3-Level AMAT Calculation with Real Hardware Latencies

📐 WORKED PROBLEM

L1 Hit = 1 ns (miss rate 5%), L2 Hit = 4 ns (miss rate 20%), L3 Hit = 15 ns (miss rate 10%), DRAM = 80 ns

Step 1 Compute L3 Effective Miss Penalty
$$\text{Penalty}_{\text{L3}} = t_{\text{L3\_hit}} + m_{\text{L3}} \times t_{\text{DRAM}} = 15 + (0.10 \times 80) = 15 + 8 = 23\text{ ns}$$
Step 2 Compute L2 Effective Miss Penalty
$$\text{Penalty}_{\text{L2}} = t_{\text{L2\_hit}} + m_{\text{L2}} \times \text{Penalty}_{\text{L3}} = 4 + (0.20 \times 23) = 4 + 4.6 = 8.6\text{ ns}$$
Step 3 Compute Overall AMAT
$$\text{AMAT} = t_{\text{L1\_hit}} + m_{\text{L1}} \times \text{Penalty}_{\text{L2}} = 1 + (0.05 \times 8.6) = 1 + 0.43 = \mathbf{1.43\text{ ns}}$$
👁️ Click to Reveal Final Verification & Answer
Effective AMAT is 1.43 ns. The 3-level cache hierarchy reduces average memory access time from 80 ns down to 1.43 ns (a 56× acceleration!).

# Worked Numerical 3: IEEE-754 Single-Precision Floating Point Representation

📐 WORKED PROBLEM

Encode -13.625 into IEEE-754 32-Bit Single Precision Format

Step 1 Determine Sign Bit (S)
Number is negative $\implies S = 1$ (1 bit).
Step 2 Convert Integer & Fraction to Binary
$13_{10} = 1101_2$. $0.625_{10} = 0.5 + 0.125 = 2^{-1} + 2^{-3} = 0.101_2$. Total binary: $1101.101_2$.
Step 3 Normalize into Scientific Notation
$$1101.101_2 = 1.101101_2 \times 2^3$$ Mantissa fraction bits = $101101000...$ (23 bits).
Step 4 Compute Biased Exponent (E)
Exponent = 3. Bias for single-precision is 127. $\text{Biased Exponent} = 3 + 127 = 130_{10} = 10000010_2$ (8 bits).
Step 5 Assemble 32-bit Hex Code
Bits: `1 10000010 10110100000000000000000` → In Hex: `0xC15A0000`.
👁️ Click to Reveal Final Verification & Answer
-13.625 in IEEE-754 single precision is represented as hex `0xC15A0000`.

# 🎯 Top Tech Interview Flashcards & Defenses

# 🎯 High-Yield Computer Architecture Interview Flashcards

What are the 3 C's of Cache Misses (and the 4th Coherence Miss)?
P1 Architecture Classic
1. **Compulsory (Cold) Misses**: First-ever access to a memory block. Unavoidable unless hardware prefetching is used. 2. **Capacity Misses**: Cache is simply too small to contain all working set blocks accessed by the program. Solved by increasing cache capacity. 3. **Conflict Misses**: Multiple active blocks map to the exact same cache set in direct-mapped or set-associative caches. Solved by increasing associativity (e.g. 4-way to 8-way). 4. **Coherence Misses**: In multicore systems, a cache line is invalidated because another core modified a shared variable on that line (MESI invalidation).
Rate Recall:
Why is row-major matrix traversal ~10x faster than column-major in C/C++?
P1 Performance Engineering
In C and C++, 2D arrays are stored in **Row-Major Order** in memory (all elements of row 0 consecutively, followed by row 1). When you read `A[i][j]`, a 64-byte cache line is loaded into L1 containing 8 consecutive 64-bit doubles (`A[i][0]` through `A[i][7]`). Sequential row iteration hits L1 cache for the next 7 elements (100% spatial locality). Column-major iteration (`A[j][i]`) jumps by $N \times 8$ bytes on every iteration, causing a compulsory cache miss on every single access!
Rate Recall:
How does Little-Endian differ from Big-Endian, and how do you test it in C?
P1 Hardware / Embedded
In Little-Endian systems (x86, ARM default), the Least Significant Byte (LSB) is stored at the lowest memory address. In Big-Endian (network byte order), the Most Significant Byte (MSB) is stored at the lowest address. C detection code: `uint16_t x = 0x0001; return *(char*)&x == 1;` (returns true for Little-Endian).
Rate Recall:
How does a 2-bit Saturating Counter Branch Predictor outperform a 1-bit predictor on loops?
P1 Microarchitecture
In a loop of 10 iterations, a 1-bit predictor mispredicts TWICE: once when exiting the loop (switches from Taken to Not Taken), and once when re-entering the loop in the next invocation (predicts Not Taken, but loop repeats). A 2-bit saturating counter has 4 states (Strongly Taken, Weakly Taken, Weakly Not Taken, Strongly Not Taken). A single exit condition only transitions Strongly Taken down to Weakly Taken! When the loop runs again, it still predicts Taken. A 2-bit predictor mispredicts only ONCE per loop.

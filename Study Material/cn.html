# TCP 3-Way Handshake, 4-Way Teardown & TIME_WAIT (2×MSL)

TCP Handshake & Teardown Protocol State Machine
🔍
TIP Why Does TCP TIME_WAIT Last for 2×MSL (Maximum Segment Lifetime)?
MSL is the maximum time a packet can wander in an IP network before being dropped by routers (default 60s, so 2×MSL = 2 minutes or 60s in Linux). 1. **Acknowledge Final ACK Delivery**: Host A sends the final ACK (Step 4). If that ACK is dropped in the network, Host B will retransmit its FIN. If Host A did not linger in `TIME_WAIT`, it would respond with an RST error, causing Host B to think the connection crashed abnormally instead of clean close! 2. **Prevent Stale Packet Contamination**: Ensures old duplicate packets lingering in network routers from this connection expire before a new socket is opened with the same IP and Port tuple.
IMPORTANT HFT Low-Latency Callout: Nagle's Algorithm vs Delayed ACKs
• **Nagle's Algorithm** (`RFC 896`): Delays sending small TCP packets until previous packets are ACKed to avoid bandwidth waste on tiny headers. • **Delayed ACK**: Receiver waits up to 200ms before sending an ACK to piggyback on outgoing data. • **The Deadlock**: Nagle waits for an ACK; the receiver waits for data to piggyback the ACK! Result: 200ms latency cliff on every RPC! • **Fix**: Disable Nagle immediately in low-latency systems via `setsockopt(fd, IPPROTO_TCP, TCP_NODELAY, &opt, sizeof(opt))`.

# The Complete URL Lifecycle: What Happens When You Type google.com

DNS Hierarchical Resolution Chain
🔍
TIP The 8-Phase End-to-End Interview Narrative
1. **Browser Cache & OS Resolution**: Checks Browser DNS cache → OS hosts file & cache → Local DNS resolver. 2. **Recursive DNS Resolution**: Recursive resolver queries Root (.) → TLD (.com) → Authoritative nameserver to obtain IP A/AAAA record. 3. **ARP (Address Resolution Protocol)**: If target IP is local or gateway router IP is needed, OS broadcasts ARP request to resolve MAC address. 4. **TCP 3-Way Handshake**: Client sends SYN → Server responds SYN-ACK → Client responds ACK. Connection established in 1 RTT. 5. **TLS 1.3 Cryptographic Handshake**: ClientHello (with supported ciphers & KeyShare) → ServerHello (KeyShare, Cert, Finished) → 1 RTT secure channel (or 0-RTT on session resumption). 6. **HTTP/2 Request**: Client sends binary multiplexed HTTP frame (`GET / HTTP/2`). 7. **Server Processing**: Reverse proxy (Nginx) → Gateway → Load Balancer → App service executes business logic and returns HTTP 200 with HTML body. 8. **DOM / CSSOM & Rendering**: Browser parses HTML to DOM, CSS to CSSOM, computes Render Tree, executes Layout/Reflow, paints pixels to GPU.

# 📐 Worked Numericals: BDP, VLSM & Ethernet Framing

# Worked Numerical 1: Bandwidth-Delay Product (BDP) & Window Sizing

\text{BDP} = \text{Bandwidth (bits/sec)} \times \text{RTT (sec)}
🗣️ Spoken Reading: Bandwidth Delay Product represents the volume of unacknowledged data in flight required to fill the network pipe
SymbolMeaning & Units
\text{Bandwidth}Bottleneck transmission rate of the link in bits per second.
\text{RTT}Round Trip Time in seconds.
\text{Window Size}TCP Receive Window buffer must equal or exceed BDP to prevent sender stalling.
🎯 Practical System Takeaway: Standard 16-bit TCP header window is capped at 65,535 bytes (64KB). On high-bandwidth links, TCP Window Scaling option (RFC 1323) is mandatory to fill the pipe!
📐 WORKED PROBLEM

Calculate BDP for a 1 Gbps Trans-Atlantic Fiber Link with 80 ms RTT

Step 1 Convert Units
Bandwidth = $1\text{ Gbps} = 10^9\text{ bits/sec}$. RTT = $80\text{ ms} = 0.08\text{ sec}$.
Step 2 Calculate BDP in Bits
$$\text{BDP} = 10^9 \times 0.08 = 80,000,000\text{ bits}$$
Step 3 Convert to Bytes
$$\text{BDP} = \frac{80,000,000}{8} = 10,000,000\text{ bytes} \approx 10\text{ MB}$$
Step 4 Determine Window Scaling
A standard 64KB TCP window can only achieve throughput of $64\text{KB} / 80\text{ms} = 6.4\text{ Mbps}$ (less than 1% of the 1Gbps pipe!). The TCP Window Scale factor must be at least $\ge 8$ ($2^8 = 256$) to support a 10MB window.
👁️ Click to Reveal Final Verification & Answer
BDP is 10 MB. Without TCP Window Scaling, a 1 Gbps link operates at less than 1% capacity due to sender stalling.

# Worked Numerical 2: VLSM Subnetting for 3 Unequal Departments

📐 WORKED PROBLEM

Subnet 192.168.1.0/24 into 3 Subnets for Sales (100 hosts), Dev (50 hosts), HR (25 hosts)

Step 1 Sort Subnets by Size (Largest First)
Sales needs 100 hosts, Dev needs 50 hosts, HR needs 25 hosts.
Step 2 Subnet 1: Sales (100 Hosts)
Need $2^h - 2 \ge 100 \implies h = 7$ bits ($2^7 - 2 = 126$ usable hosts). Subnet mask: $32 - 7 = /25$ (255.255.255.128). Network: 192.168.1.0/25. Host range: 192.168.1.1 to 192.168.1.126. Broadcast: 192.168.1.127.
Step 3 Subnet 2: Dev (50 Hosts)
Need $2^h - 2 \ge 50 \implies h = 6$ bits ($2^6 - 2 = 62$ usable hosts). Subnet mask: $32 - 6 = /26$ (255.255.255.192). Network: 192.168.1.128/26. Host range: 192.168.1.129 to 192.168.1.190. Broadcast: 192.168.1.191.
Step 4 Subnet 3: HR (25 Hosts)
Need $2^h - 2 \ge 25 \implies h = 5$ bits ($2^5 - 2 = 30$ usable hosts). Subnet mask: $32 - 5 = /27$ (255.255.255.224). Network: 192.168.1.192/27. Host range: 192.168.1.193 to 192.168.1.222. Broadcast: 192.168.1.223.
👁️ Click to Reveal Final Verification & Answer
Successfully partitioned without address overlap: Sales (/25), Dev (/26), and HR (/27), preserving remaining space from 192.168.1.224 for future growth.

# 🎯 High-Yield Computer Networks Interview Flashcards

Why is TCP 3-Way Handshake necessary instead of a 2-Way Handshake?
P1 Network Systems
Both client and server must agree on each other's Initial Sequence Numbers (ISNs) to establish bidirectional reliable communication. In a 2-way handshake, if an old delayed SYN packet wanders through the network and arrives at the server after the original connection terminated, the server would send SYN-ACK and immediately allocate resources believing a new connection opened! Host A never sent that SYN, so it ignores the ACK. The server is left holding a half-open ghost connection that wastes memory.
Rate Recall:
How does HTTP/3 with QUIC solve Head-of-Line (HoL) Blocking compared to HTTP/2?
P1 Modern Web / Systems
HTTP/2 multiplexes multiple application requests as virtual streams over a SINGLE underlying TCP connection. If a single TCP packet containing Stream 1 data is dropped, the TCP stack buffers all subsequent packets in the OS socket buffer until the dropped packet is retransmitted and acknowledged. Consequently, Streams 2, 3, and 4 are blocked, even though none of their packets were dropped! HTTP/3 runs over QUIC (UDP), implementing stream multiplexing at the transport layer directly: dropping a packet for Stream 1 has ZERO impact on Streams 2, 3, and 4.
Rate Recall:
Why does Ethernet enforce a 64-Byte Minimum Frame Size?
P1 Hardware / Systems
In classic Ethernet using CSMA/CD, a sender must continue transmitting data long enough to detect a collision from the furthest possible station on the cable before finishing its transmission ($T_{\text{tx}} \ge 2 \times T_{\text{prop}}$). At 10 Mbps over a maximum cable length of 2500m (with repeaters), round-trip propagation delay is ~51.2 µs. In 51.2 µs, a 10 Mbps transceiver outputs $51.2 \times 10 = 512\text{ bits} = 64\text{ bytes}$. If a frame was smaller than 64 bytes, transmission would finish before the collision signal returned, causing undetected corrupted frames!
Rate Recall:
What is the difference between ARP and RARP?
P1 Campus Classic
ARP (Address Resolution Protocol) resolves a known Layer 3 logical IP address to a physical Layer 2 MAC address using broadcast requests and unicast replies. RARP (Reverse ARP) allows a diskless workstation to query a server to find its own IP address given its known hardware MAC address upon boot (superseded by BOOTP and DHCP).

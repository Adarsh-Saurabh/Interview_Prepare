The paradigm of bundling state (attributes) and behavior (methods)

0.4 Pillar 1: Encapsulation & Data Hiding in Python The 4 Pillars
Protecting internal state without dogmatic access specifiers

Encapsulation is the bundling of data and the methods that operate on that data into a single unit, while restricting direct access to internal components.

Unlike Java or C++, Python has no private keyword. Python follows the philosophy: "We are all consenting adults here."

  1. Public Attributes: self.name (accessible freely from outside).
  2. Protected Convention: self._balance (single leading underscore; signals to developers: internal, do not touch outside class/subclasses).
  3. Private (Name Mangling): self.__pin (double leading underscore; Python automatically rewrites the attribute internally as _ClassName__pin to prevent accidental overrides in subclasses).
  4. Property Decorators (@property): Encapsulate getters, setters, and deleters with validation!
class SecureAccount:
    def __init__(self, owner: str, balance: float, pin: int):
        self.owner = owner        # Public
        self._balance = balance   # Protected convention
        self.__pin = pin          # Private (mangled to _SecureAccount__pin)

    @property
    def balance(self) -> float:
        """Getter: Read-only access or computed property"""
        return self._balance

    @balance.setter
    def balance(self, value: float):
        """Setter with validation logic"""
        if value < 0:
            raise ValueError("Balance cannot be negative!")
        self._balance = value

acc = SecureAccount("Adarsh", 5000, 1234)
print(acc.balance)       # 5000 (Calls getter)
acc.balance = 6000       # Calls setter
# acc.balance = -100     # Raises ValueError!

# Demonstrating Name Mangling:
# print(acc.__pin)       # Raises AttributeError!
print(acc._SecureAccount__pin) # 1234 (Accessible via mangled name; not truly secret)
0.5 Pillar 2: Abstraction & Abstract Base Classes (ABCs) The 4 Pillars
Hiding complex implementation details and exposing a clean interface

Abstraction means showing only essential features of an entity while hiding underlying complex implementation details. For example, when you drive a car, you press the gas pedal (simple interface); you don't need to manually orchestrate fuel injection or combustion timing (hidden complexity).

  • Python implements formal abstraction via the abc module: ABC (Abstract Base Class) and @abstractmethod.
  • Rule: A class with at least one abstract method cannot be instantiated!
  • Subclasses must override and implement all abstract methods, or they too remain abstract and cannot be instantiated.
from abc import ABC, abstractmethod

class PaymentGateway(ABC):
    """Abstract Base Class (Interface Contract)"""
    @abstractmethod
    def process_payment(self, amount: float) -> bool:
        """Subclasses MUST implement this method!"""
        pass

    @abstractmethod
    def refund(self, transaction_id: str) -> bool:
        pass

# Attempting to instantiate ABC directly:
# p = PaymentGateway() # Raises TypeError: Can't instantiate abstract class!

class StripeGateway(PaymentGateway):
    def process_payment(self, amount: float) -> bool:
        print(f"Processing ${amount} via Stripe API...")
        return True

    def refund(self, transaction_id: str) -> bool:
        print(f"Refunding transaction {transaction_id} via Stripe...")
        return True

stripe = StripeGateway()
stripe.process_payment(250.0) # Works perfectly!
0.6 Pillar 3: Inheritance & super() Mechanics The 4 Pillars
Reusing code, establishing 'Is-A' relationships, and calling parents

Inheritance allows a child class (subclass) to inherit attributes and methods from a parent class (superclass), promoting code reuse.

  • Single Inheritance: Child inherits from 1 parent.
  • Hierarchical Inheritance: Multiple children inherit from 1 parent.
  • Multilevel Inheritance: Child inherits from Parent, which inherits from Grandparent.
  • Multiple Inheritance: Child inherits from multiple parents: class C(A, B).
  • super(): Used to call parent class methods without hardcoding parent names.
class Vehicle:
    def __init__(self, brand: str, max_speed: int):
        self.brand = brand
        self.max_speed = max_speed

    def describe(self):
        return f"{self.brand} running up to {self.max_speed} km/h"

class ElectricCar(Vehicle):
    def __init__(self, brand: str, max_speed: int, battery_kwh: int):
        # Call parent constructor using super():
        super().__init__(brand, max_speed)
        self.battery_kwh = battery_kwh

    # Method Overriding (Extending parent behavior):
    def describe(self):
        base_desc = super().describe()
        return f"{base_desc} with a {self.battery_kwh} kWh battery"

0.7 Pillar 4: Polymorphism & Duck Typing The 4 Pillars
Different classes responding to the identical method invocation

Polymorphism ("many forms") allows different classes to define methods with the exact same name, so a caller can interact with them uniformly without knowing their specific underlying class.

  • Duck Typing (Python's core philosophy): "If it walks like a duck and quacks like a duck, it's a duck." Python does not check variable types at compile time; it simply checks whether the object supports the called method at runtime!
  • Operator Overloading: Giving custom meaning to standard Python operators (+, -, len(), ==) using magic dunder methods.
  • Method Overriding vs Overloading:
    • Overriding: Subclass provides a specific implementation of a method already defined in parent class.
    • Overloading: Defining multiple methods with the same name but different argument signatures. Python does NOT support traditional overloading by signature! Later definitions overwrite earlier ones. Achieve it via default arguments, *args, or functools.singledispatch.

0.8 Composition vs Inheritance ("Favor Composition Over Inheritance") Architecture
Is-A relationship vs Has-A relationship in real-world systems

One of the most frequent senior architecture interview questions: "Why should you favor composition over inheritance?"

  • Inheritance ("Is-A"): Tightly couples the subclass to the parent. Changes in parent class cascade down and break subclasses (Fragile Base Class Problem). Python allows only static inheritance at class creation time.
  • Composition ("Has-A"): A class contains instances of other classes as attributes. Components can be swapped dynamically at runtime, dependencies are loosely coupled, and unit testing is trivial with mocks.
# INHERITANCE ANTI-PATTERN: Tightly coupled, fragile
class Engine:
    def start(self): return "Engine Vroom!"

class CarBad(Engine): # Car IS NOT an Engine! This violates modeling logic!
    pass

# COMPOSITION PATTERN (Clean & Extensible):
class GasolineEngine:
    def start(self): return "Gasoline engine roaring!"

class ElectricMotor:
    def start(self): return "Electric motor silent hum..."

class ModernCar:
    # Car HAS AN engine
    def __init__(self, engine):
        self.engine = engine # Injected component!

    def drive(self):
        print(self.engine.start())
        print("Car moving forward smoothly.")

# Engine can be swapped dynamically at runtime!
gas_car = ModernCar(GasolineEngine())
gas_car.drive()

ev_car = ModernCar(ElectricMotor())
ev_car.drive()

1.1 CPython Compilation Pipeline & Stack VM Architecture
How Python converts source text to running machine instructions

Python is an interpreted, bytecode-compiled language. The standard implementation (CPython) executes code in four distinct phases:

  1. Tokenizing & Parsing: Source .py is converted to Parse Tree, then into an Abstract Syntax Tree (AST).
  2. Bytecode Compilation: AST is compiled into platform-independent bytecode instructions represented as PyCodeObject (cached in __pycache__/*.pyc).
  3. Stack-based Virtual Machine: The CPython runtime (ceval.c) evaluates bytecode inside an evaluation loop using an evaluation stack (no hardware registers).
  4. Frame Objects (PyFrameObject): Every function call allocates a frame on the C-call stack containing: local variable array (fast access LOAD_FAST), value evaluation stack, and reference to globals/built-ins.

3.4 MRO & The C3 Linearization Algorithm Diamond Inheritance
How Python resolves method calls in multiple inheritance

Python calculates Method Resolution Order (MRO) using the C3 Linearization Algorithm:

C3 Formula: \(L[C(B_1, \dots, B_n)] = C + \text{merge}(L[B_1], \dots, L[B_n], B_1, \dots, B_n)\)
The merge operation takes the first head of a list that does not appear in the tail of any other list. 
class O: pass
class A(O): pass
class B(O): pass
class C(A, B): pass

# Trace:
# L[O] = [O]
# L[A] = [A, O]
# L[B] = [B, O]
# L[C] = [C] + merge([A, O], [B, O], [A, B])
# Step 1: Head 'A' not in tails -> Select 'A' -> [C, A] + merge([O], [B, O], [B])
# Step 2: Head 'O' IS in tail of [B, O]! Skip 'O', check next list head 'B'.
# Step 3: 'B' not in tails -> Select 'B' -> [C, A, B] + merge([O], [O])
# Step 4: Select 'O' -> Result: [C, A, B, O]

print(C.__mro__)  # (C, A, B, O, object)

4.1 CPython Memory Management & PyMalloc Memory Allocator
Hierarchical allocation architecture: Arenas, Pools, and Blocks

To avoid operating system malloc() overhead and kernel context switches for millions of small allocations, CPython implements a dedicated Small Object Allocator (PyMalloc) for objects ≤ 512 bytes:

  • Arenas (256 KB): Contiguous virtual memory allocated via OS malloc()/mmap. Only arenas can be freed back to the OS!
  • Pools (4 KB): 1 arena contains 64 pools. Each pool handles objects of a single fixed size class (multiples of 8 bytes: 8, 16, 24 ... 512 bytes).
  • Blocks (8 to 512 Bytes): Carved out of pools to hold individual PyObject payloads.
  • Large Objects (> 512 Bytes): Bypasses PyMalloc completely and routes directly to system malloc().
Memory Fragmentation Trap: Why does Python process memory not decrease after deleting millions of objects? Because if an Arena has even ONE single 16-byte object still in use, the entire 256 KB arena cannot be returned to the OS kernel!
4.2 Garbage Collection: Ref Counting + Generational Cyclic GC Garbage Collection
Immediate O(1) deallocation and circular reference detection
  1. Reference Counting (Primary Engine):
    • Every PyObject tracks ob_refcnt.
    • Incremented on assignment, argument passing, appending to list.
    • Decremented on del, variable out of scope, list clearing.
    • When ob_refcnt == 0, memory is immediately and deterministically deallocated!
  2. Generational Cyclic GC (Secondary Engine):
    • Solves circular references: a.b = b; b.a = a; del a; del b (ref count never reaches 0).
    • Only tracks container objects (lists, dicts, custom classes, tuples). Immutable non-containers (int, str) are ignored.
    • 3 Generations (Gen 0, Gen 1, Gen 2):
      • Gen 0: Newly allocated containers. Collected frequently.
      • Gen 1: Survived Gen 0 collections. Collected moderately.
      • Gen 2: Long-lived objects. Collected rarely.
    • Trial Deletion Algorithm: GC copies ref counts to gc_refs, traverses container references, decrements gc_refs for internal links. Objects with gc_refs == 0 are strictly cyclic and unreachable -> collected!
import gc, weakref

class Node:
    def __init__(self, val):
        self.val = val
        self.neighbor = None

a = Node(1); b = Node(2)
a.neighbor = b; b.neighbor = a # Cyclic Reference!
del a; del b # Ref count remains 1 for both!

print(gc.collect()) # Forces cyclic collection; returns number of reclaimed objects

# Preventing Memory Leaks: Use weakref (does not increment ob_refcnt!)
class SafeGraphNode:
    def __init__(self, val):
        self.val = val
        self._parent = None
    @property
    def parent(self):
        return self._parent() if self._parent else None
    @parent.setter
    def parent(self, obj):
        self._parent = weakref.ref(obj) # Weak reference!
4.3 The Global Interpreter Lock (GIL) Mechanics Concurrency
Why Python threads cannot run parallel CPU bytecode on multiple cores

The GIL is a mutual exclusion lock implemented in CPython to protect internal memory structures and prevent race conditions on ob_refcnt.

  • Only one OS thread can execute Python bytecode at any given instant, even on a 64-core CPU!
  • Switch Interval (sys.setswitchinterval(0.005)): Every 5 milliseconds, the executing thread releases the GIL so other waiting threads can acquire it (cooperative multitasking).
  • I/O Bound Tasks: Python threads voluntarily release the GIL while waiting on network sockets, file reads, or sleep! Thus, threading is highly effective for web scrapers, API fetchers, and DB calls.
  • CPU Bound Tasks: Multiple threads fighting for the GIL cause massive thread context-switch thrashing, running slower than a single-threaded loop!
AI / Data Science Superpower: C-Extensions like NumPy, PyTorch, SciPy, and OpenCV release the GIL during heavy matrix math (via Py_BEGIN_ALLOW_THREADS). Pure tensor operations execute in parallel across all CPU cores!

Modern Update (Python 3.12/3.13): PEP 703 (Free-Threaded CPython) removes the GIL entirely using biased reference counting and mimalloc; PEP 684 introduces Per-Interpreter GIL.

Q52 How are Python dictionaries implemented under the hood in modern CPython (3.6+)? ▼
Detailed Answer:

Modern CPython uses a Compact, Ordered Hash Table (designed by Raymond Hettinger / PyPy). Older dictionaries had a sparse table where each slot held 24 bytes (hash, key, value), wasting ~60% memory.

The compact design splits storage into two tables:

  1. Indices Array (Sparse): A flat array of small integers (e.g. int8 or int16) acting as a hash-indexed table.
  2. Entries Array (Dense): A dense array of [hash, key_ptr, value_ptr] structs appended in insertion order!

Benefits: 30–40% memory savings, and insertion order is preserved by default with zero performance penalty!

Q53 How does Python's hash table resolve hash collisions? ▼
Detailed Answer:

Python uses Open Addressing with a Random Perturbation Sequence, NOT separate chaining with linked lists (like Java HashMap).

When a collision occurs at index \(i\), Python calculates the next probe index using:

// CPython Objects/dictobject.c
j = ((5 * j) + 1 + perturb) & mask;
perturb >>= 5;

Why this matters: Pure linear probing (\(i+1\)) suffers from severe primary clustering. Incorporating the top bits of the hash code via perturb >>= 5 scrambles the probe sequence across the entire table, maintaining \(O(1)\) amortized lookup even under heavy loads.

Q58 What is the Diamond Inheritance Problem and how does Python solve it? ▼
Detailed Answer:

In a diamond hierarchy where class D inherits from both B and C, which both inherit from A, a naive depth-first search would visit A before C, breaking the rule that subclasses must override superclasses.

Python resolves this using the C3 Linearization Algorithm, ensuring two properties:

  1. Local Precedence Order: Direct parent classes are evaluated in the exact order declared in the class definition tuple class D(B, C).
  2. Monotonicity: A class always appears before its parents in the MRO of any subclass.

D.__mro__ evaluates to (D, B, C, A, object).

Q76 What is the Global Interpreter Lock (GIL) and why was it implemented in CPython? ▼
Detailed Answer:

The GIL is a mutex preventing multiple native OS threads from executing CPython bytecode simultaneously. It exists because CPython's memory management is NOT thread-safe: reference counting (ob_refcnt) requires atomic updates. Without the GIL, every single pointer assignment, argument passing, and destruction in Python would require fine-grained locks, crippling single-threaded performance by 2–3x and complicating C-extension integration.

Q77 Why does multi-threading make CPU-bound Python programs run SLOWER than single-threaded execution? ▼
Detailed Answer:

When multiple threads attempt to run CPU-intensive Python bytecode, they cannot execute in parallel due to the GIL. Every 5ms (sys.getswitchinterval()), the OS signals the active thread to yield the GIL. The waiting threads contend for the lock via OS condition variables, causing massive CPU cache invalidation, thread context-switch overhead, and OS scheduling thrashing (the Convoy Effect). The overhead of fighting for the lock adds 20–40% extra latency compared to a single thread!

Q78 How do C-extensions like NumPy and PyTorch achieve true multi-core CPU parallelism in Python? ▼
Detailed Answer:

Through CPython's C-API macros: Py_BEGIN_ALLOW_THREADS and Py_END_ALLOW_THREADS. When NumPy or PyTorch performs heavy matrix multiplication or tensor transformations, the C code explicitly releases the GIL, allowing other Python threads to execute while native C/Fortran/BLAS/OpenMP threads compute in parallel across all CPU cores!

Q79 What is the difference between threading.Lock and threading.RLock? ▼
Detailed Answer:
  • threading.Lock: A non-reentrant standard mutex. If a thread attempts to acquire the lock while already holding it, the thread deadlocks itself permanently!
  • threading.RLock: A Reentrant Lock. It tracks the owning thread ID and a recursion count. The same thread can acquire the lock multiple times without blocking. The lock is only released to other threads when the recursion count decrements back to zero. Essential for recursive methods and class methods that call other synchronized methods.

When a coroutine hits await socket.read(), it yields control back to the event loop. The OS notifies the event loop when data arrives on the file descriptor, and the loop resumes the paused coroutine.

A Circuit Breaker has three states: CLOSED (normal operations), OPEN (failing; fail-fast immediately without sending network requests), and HALF_OPEN (testing if the external service has recovered).

import time

class CircuitBreakerOpenException(Exception): pass

class CircuitBreaker:
    def __init__(self, failure_threshold=5, recovery_timeout=60):
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.failure_count = 0
        self.last_failure_time = 0
        self.state = "CLOSED"

    def __call__(self, func):
        def wrapper(*args, **kwargs):
            now = time.time()
            if self.state == "OPEN":
                if now - self.last_failure_time > self.recovery_timeout:
                    self.state = "HALF_OPEN"
                else:
                    raise CircuitBreakerOpenException("Circuit OPEN: Failing fast!")

            try:
                result = func(*args, **kwargs)
                if self.state == "HALF_OPEN":
                    self.state = "CLOSED"
                    self.failure_count = 0
                return result
            except Exception as e:
                self.failure_count += 1
                self.last_failure_time = now
                if self.failure_count >= self.failure_threshold:
                    self.state = "OPEN"
                raise e
        return wrapper

Doubly Linked List + Hash Map + Reentrant Lock

import threading
from typing import Any, Optional

class Node:
    __slots__ = ('key', 'val', 'prev', 'next')
    def __init__(self, key: Any = None, val: Any = None):
        self.key = key
        self.val = val
        self.prev: Optional['Node'] = None
        self.next: Optional['Node'] = None

class ThreadSafeLRUCache:
    def __init__(self, capacity: int):
        if capacity <= 0:
            raise ValueError("Capacity must be positive!")
        self.capacity = capacity
        self.map: dict[Any, Node] = {}
        self.lock = threading.RLock() # Reentrant thread safety

        # Sentinel dummy head and tail nodes to eliminate edge-case branching
        self.head = Node()
        self.tail = Node()
        self.head.next = self.tail
        self.tail.prev = self.head

    def _remove(self, node: Node) -> None:
        """Detach node from doubly linked list in O(1)"""
        node.prev.next = node.next
        node.next.prev = node.prev

    def _add_to_front(self, node: Node) -> None:
        """Insert node immediately after sentinel head (Most Recently Used)"""
        node.next = self.head.next
        node.prev = self.head
        self.head.next.prev = node
        self.head.next = node

    def get(self, key: Any) -> Any:
        with self.lock:
            if key not in self.map:
                return -1
            node = self.map[key]
            self._remove(node)
            self._add_to_front(node)
            return node.val

    def put(self, key: Any, value: Any) -> None:
        with self.lock:
            if key in self.map:
                node = self.map[key]
                node.val = value
                self._remove(node)
                self._add_to_front(node)
            else:
                if len(self.map) >= self.capacity:
                    # Evict Least Recently Used (node before sentinel tail)
                    lru = self.tail.prev
                    self._remove(lru)
                    del self.map[lru.key]

                new_node = Node(key, value)
                self.map[key] = new_node
                self._add_to_front(new_node)

import threading, weakref
from collections import defaultdict
from typing import Callable, Any

class EventBus:
    """Thread-safe publish-subscribe event dispatcher preventing memory leaks"""
    _instance = None
    _lock = threading.Lock()

    def __new__(cls):
        if not cls._instance:
            with cls._lock:
                if not cls._instance:
                    cls._instance = super().__new__(cls)
                    cls._instance._subscribers = defaultdict(weakref.WeakSet)
                    cls._instance._bus_lock = threading.RLock()
        return cls._instance

    def subscribe(self, topic: str, callback: Callable[[Any], None]) -> None:
        """Registers a subscriber using a weak reference"""
        with self._bus_lock:
            # Handles both bound methods and standalone functions
            self._subscribers[topic].add(callback)

    def publish(self, topic: str, data: Any) -> None:
        """Dispatches event to all active subscribers for the topic"""
        with self._bus_lock:
            listeners = list(self._subscribers.get(topic, []))

        for listener in listeners:
            try:
                listener(data)
            except Exception as e:
                # Isolate exceptions so one subscriber does not crash others
                print(f"[EventBus Error] Listener {listener} failed on topic {topic}: {e}")

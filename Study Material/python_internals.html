⚡ 10-Minute Rapid Recall Cheat Sheet

Python Under The Hood

1. Python Concurrency Models: Threading vs Multiprocessing vs AsyncIO

Model Underlying Primitive Subject to GIL? Ideal Workload Memory & Context Switch Cost
threading Real OS Threads (POSIX threads) YES (Only 1 thread runs Python code at a time). I/O-bound tasks (network requests, DB queries, reading files). Low memory (~8MB stack per thread); OS context switches.
multiprocessing Separate OS Processes via fork() / spawn NO (Each process has its own independent Python interpreter and GIL!). CPU-bound heavy compute (ML data prep, image processing, cryptography). High memory (duplicates process memory); IPC serialization overhead via pickle.
asyncio Single-threaded Event Loop + Coroutines N/A (Single-threaded cooperative multitasking). High-concurrency network servers (10,000+ simultaneous open sockets). Extremely lightweight (< 1KB per coroutine); zero OS context switches!

2. High-Frequency Python Dunder (Magic) Methods

Dunder Method When It Triggers Interview Trap / Note
__new__(cls, ...) Creates and returns the new instance memory before initialization. Called before __init__; used for Singletons and subclassing immutable types (int, tuple).
__init__(self, ...) Initializes instance attributes after creation. Must return None; cannot create the object itself.
__call__(self, ...) Enables instance to be invoked as a function: obj(). Used in custom Decorators, Neural network layers (PyTorch nn.Module).
__enter__ & __exit__ Context Manager protocol (with open(...) as f:). __exit__ catches exceptions and guarantees resource cleanup even on error!
__slots__ Explicitly declares allowed instance attributes as a tuple. Eliminates __dict__ overhead, saving 40-50% memory per object!

🧠 GIL Mechanics, Memory & AsyncIO

Advanced Python

1. CPython Memory Architecture: PyObject Header & Reference Counting

Every single object in Python is wrapped in a C structure called PyObject: 

// CPython PyObject Definition (Include/object.h)
struct _object {
    _PyObject_HEAD_EXTRA // Doubly linked list for GC tracking
    Py_ssize_t ob_refcnt; // 64-bit reference counter
    struct _typeobject *ob_type; // Pointer to type descriptor (int, dict, etc.)
};
  • Reference Counting ($O(1)$ Instant Cleanup): Whenever an object is referenced (assignment, passed to function), ob_refcnt increments. When reference falls out of scope, ob_refcnt decrements. When it hits $0$, memory is immediately returned to Python's memory pool (PyMalloc).
  • Cyclic Garbage Collector: Reference counting cannot detect circular references (e.g. a.b = b; b.a = a). Python uses a generational cyclic collector that finds unreachable reference cycles by isolating pointer references across tracking lists.

2. How AsyncIO Works Under the Hood (Epoll / Kqueue Event Loop)

In asyncio, execution is single-threaded cooperative multitasking: 

import asyncio

async def fetch_data():
    print("Start fetch...")
    await asyncio.sleep(1) # Yields execution back to event loop!
    print("Done fetch!")

async def main():
    # Runs both coroutines concurrently on a single OS thread!
    await asyncio.gather(fetch_data(), fetch_data())

asyncio.run(main())

When await is called, the coroutine suspends its generator frame and yields control back to the Event Loop. The event loop registers the socket file descriptor with the OS kernel's epoll (Linux) or kqueue (macOS). When data arrives, the OS notifies the loop, which wakes up the suspended coroutine.

⚠️ High-Frequency Python Traps

Recruiter Traps
Trap #1: Mutable Default Arguments Pitfall
def append_to(element, target_list=[]):
    target_list.append(element)
    return target_list

print(append_to(1)) # Output: [1]
print(append_to(2)) # Output: [1, 2] -- TRAP! Not [2]!

Why: Default function arguments are evaluated once at function definition time (when the module is loaded), NOT when the function is called! The empty list [] is shared across all subsequent invocations.

The Fix: Use None as the default sentinel value:

def append_to(element, target_list=None):
    if target_list is None:
        target_list = []
    target_list.append(element)
    return target_list
Trap #2: "is" vs "==" and Small Integer Caching
a = 256; b = 256
print(a is b) # True!

x = 257; y = 257
print(x is b) # False! (In standard REPL)

Why: == tests for equality of values. is tests for memory address identity (id(a) == id(b)). CPython pre-allocates and caches an internal array of all integers between -5 and 256 at interpreter startup! Numbers in this range always share the same memory address, whereas numbers outside this range create distinct heap objects.

🎯 10 High-Frequency GFG Interview Q&As (Self-Assessment)

10 Questions
Q1: Why does Python have a GIL and can you remove it?
CPython uses the GIL (Global Interpreter Lock) because its memory management relies on reference counting. Without the GIL, every single reference count increment and decrement would require fine-grained thread mutex locks, which would cripple single-threaded performance by 2x to 3x!
• Free-threaded Python (PEP 703): Python 3.13 introduces an experimental build option (--disable-gil) that replaces the GIL with mimalloc-based biased reference counting.
Q2: How does __slots__ save 40-50% memory in Python classes?
By default, every Python instance stores its attributes dynamically inside a dictionary (self.__dict__). A Python hash dictionary carries substantial memory overhead (hash table array, key pointers, capacity expansion).
When you define __slots__ = ('name', 'age'):
  • Python allocates a fixed-size C array of pointers instead of a dynamic dictionary.
  • No __dict__ is created for instances!
  • Attribute lookups become direct array offset indexing, reducing per-object memory from ~150 bytes to ~48 bytes.
Q3: What is the difference between copy.copy() (Shallow Copy) and copy.deepcopy()?
• Shallow Copy (copy.copy()): Constructs a new container object, but populates it with references to the objects found in the original. Modifying nested mutable objects (e.g. lists inside a list) mutates both copies!
• Deep Copy (copy.deepcopy()): Recursively clones the entire object hierarchy, copying all nested objects and circular references into brand new memory addresses.
Q4: How do Generators (yield) work and why are they memory efficient?
A regular function computes its entire result and returns it at once, allocating memory for all elements (e.g. a list of 10,000,000 integers takes ~800MB RAM).
A Generator function uses yield:
  • When yield is encountered, the function's execution state (local variables, instruction pointer) is frozen in a PyFrameObject and returned to the caller.
  • Subsequent calls to next() resume execution from where it left off.
  • Memory footprint is strictly $O(1)$ constant memory regardless of data size!
Q5: What is the difference between *args and **kwargs?
• *args collects positional arguments passed beyond the formal parameter list into a tuple.
• **kwargs collects named keyword arguments passed beyond the formal parameter list into a dictionary.
Order in function definition: def func(required, *args, default=val, **kwargs):.
Q6: What does @functools.wraps do and why is it mandatory in decorators?
When a function is wrapped by a decorator, the decorated function takes on the name and docstring of the internal wrapper function (e.g. my_func.__name__ becomes "wrapper"), breaking debugging, logging, and reflection tools.
Adding @functools.wraps(func) to the wrapper copies over the original function's metadata (__name__, __doc__, __annotations__).
Q7: How does Python's Garbage Collector detect Cyclic References?
Python uses an algorithm that tracks all container objects (lists, dicts, custom classes) in a doubly-linked list:
  1. For each container object, it sets a trial reference count equal to ob_refcnt.
  2. It iterates through all objects and decrements the trial reference count for every reference pointing from one tracked container to another.
  3. Any object whose trial count drops to 0 has all its incoming references originating from within the isolated cycle itself!
  4. These unreachable circular clusters are broken and freed.
Q8: What is Method Resolution Order (MRO) and the C3 Linearization Algorithm?
In multiple inheritance (e.g. Diamond Problem: Class D inherits from B and C, which both inherit from A), Python determines which method to execute using C3 Linearization (MRO).
It guarantees two properties: (1) Children precede their parents, and (2) The order of base classes in the class declaration is preserved. You can inspect any class's resolution order via ClassName.__mro__.
Q9: What is the difference between List Comprehension and Generator Expression?
• List Comprehension: [x*2 for x in range(1000)]. Enclosed in brackets []; evaluates eagerly and allocates full list in memory immediately.
• Generator Expression: (x*2 for x in range(1000)). Enclosed in parentheses (); evaluates lazily on-demand, consuming near zero memory.
Q10: How do you achieve true CPU parallelism in Python?
To bypass the GIL and utilize 100% of all CPU cores:
  • multiprocessing: Use concurrent.futures.ProcessPoolExecutor or multiprocessing.Pool to spawn child processes across CPU cores.
  • C / Cython Extensions: Release the GIL in C extensions during compute loops using Py_BEGIN_ALLOW_THREADS (as done in NumPy, PyTorch, OpenCV).
  • Distributed Task Workers: Use Celery or Ray to distribute tasks across cluster nodes.
